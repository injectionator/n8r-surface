# Progressive source access for first-use research

Approved in conversation on 14 November 2026; related to #76 and draft PR #82.

A newcomer can start from a short system description or deployment document,
without a Lab, repository attachment or prepared credentials. Researcher reads
available evidence, returns a small qualified map and helps make one useful next
source accessible. Setup and missing runtime access do not block source research.

## Approaches

The maintainer approved progressive onboarding within the investigation. A separate
setup questionnaire delays the first useful result. Building a new access connector
would change the product scope and is deferred. Use the host's actual capabilities.

## Behavior and boundaries

- Distinguish mentioned sources, available access routes, successful scoped reads
  and blocked/deferred sources. Keep this in ordinary notes, not a new schema.
- Guide selected files/project uploads, authorized repository connections and
  explicitly connected computers according to the current host. A web Project
  does not itself expose a laptop folder; an SSH address does not supply access.
- Ask one consequential next question, after using information already supplied.
  Explain what the next source can establish; retain a useful partial result.
- Keep credentials in supported host authentication flows. If direct access is
  unavailable, offer scoped human-collected evidence without broad raw dumps.
- Separate research readiness from local workspace setup. Check helper/runtime,
  file delivery and persistence before promising a save. A downloadable artifact
  is not a local-vault save or guaranteed future-session persistence.
- Preserve read-only boundaries, provenance, stable identities and Surface profile 1.
  No target mutation, new collector, connector, credential store or CLI permission.

## Verification

State X: installed Researcher, a fresh session and a description of a synthetic
system; source and VPS are mentioned but access is not established.
Input Y: ask to understand the system, establish sources progressively and save.
Outcome Z: a qualified initial map, a concrete supported next access step, explicit
access/save limits and no invented target access. Supply another source and verify
that the next question advances rather than repeats onboarding.

Compare current installed behavior with candidate behavior. Attempt actual web
archive installation and fresh invocation without local projects or previous
research. Keep simulations, web receipts, helper validation and human acceptance
separate. Web feature availability, helper execution and persistence remain facts
to establish in the trial, not promises made by the guidance.
